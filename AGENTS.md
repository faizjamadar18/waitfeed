# WaitFeed — Agent Instructions

Context and working rules for coding agents working in this repository.
The product story and usage docs live in [README](README.md) and the
[package README](packages/waitfeed/README.md); this file is about *developing* it.

## The lay of the land

```
packages/waitfeed/     the npm package — the publish root (its own package.json)
  core/                host-agnostic decisions: feeds, enrich, junk filter,
                       cache pipeline, config, ticker/AGY card rendering
  opencode/ · claude/ · claude-mod/ · agy/   the host adapters (OpenCode TUI
                       plugin, Claude Code data cycle + band mod, Antigravity
                       agent_state)
  bin.mjs              `npx waitfeed init` — detects hosts, stages bundles,
                       writes each host's config (idempotent); `remove`
                       reverses it all (config entries, staged files, data)
tests/                 11 vitest suites — unit + bundle E2E against built dist/
frontend/              Next.js 16 landing page (its AGENTS.md is generated by
                       `next dev` — commit it)
scripts/               feed channel health probe
```

Architecture in one line: every adapter renders from the SAME
`~/.config/waitfeed/cache.json` (a shared fetch → enrich → junk-drop
pipeline, cycle-lock serialized); busy/idle gating is per host — OpenCode
session state, AGY `agent_state`, Claude Code's own `isWorking` in the band.
Renders only READ the cache; they never fetch.

## Commands (repo root)

| Command | Does |
| --- | --- |
| `npm ci` | dev harness (vitest, tsc, esbuild) — **plus** `npm install --legacy-peer-deps` in `packages/waitfeed` for the package tree (tests and bundles resolve `rss-parser` & co. from there) |
| `npm run typecheck` | strict `tsc --noEmit` over tests + packages |
| `npm test` | `pretest` (builds agy+claude bundles) then all suites |
| `npm run preview` | `npm pack --dry-run` from the publish root — exactly what npm would publish |
| `npm run init` | run the init wizard against this machine |

## Working agreements

- TDD for behavior changes: Red (a failing contract) → Green → keep the contract.
- **Design one interaction past the literal ask.** Before implementing, enumerate
  the conflicts a change creates with keys, focus, and sizing, and state the
  decision visibly: what moves a cursor whose natural keys (↑/↓) are already
  bound, what the on-screen hint must say, what overrides what at the
  edges. A shipped UI only promises what the visible hint says.
- Do NOT run verifications on every prompt cycle; full runs (`npx tsc --noEmit`, `npx vitest run`, lint) only on explicit request or at a release.
- Zero-warning standard: no unused imports/variables, standard utility classes, no stray files.
- Keep changes small and consistent; this is a public open-source repo (MIT).

## Hard boundaries

1. **Never commit or push without the user's explicit YES.**
2. **No API keys, no secrets, no `.env` — keyless by design.**
3. **Never swallow user keystrokes** — hide-on-type must never intercept input.
4. **Stay observational** — never modify prompts, tools, or agent behavior.
5. Verify host APIs against the CURRENT docs before use — these APIs are young.

## Verified gotchas (learned the hard way — trust these)

OpenCode adapter, v2 plugin API (docs: <https://opencode.ai/v2/docs/build/plugins>):

- Zero LLM tokens: OpenCode uses the shared Headline + Description + Link pipeline (same as Claude and Antigravity) — 0 tokens, 0 API keys, completely free.
- The host re-runs plugin `setup` once per active session — assume concurrent setups; the stale-TTL `cycle.lock` handles it.
- The host runs Node 20 but `@effect/platform-node` pulls `undici@8` (needs Node ≥22) — top-level undici v8 makes the plugin fail to load SILENTLY. Keep `overrides: { "undici": "6.29.1" }`; reinstall with `npm install --legacy-peer-deps`.

OpenCode adapter, display invariants:

- Descriptions are stored up to 600 chars (`CONTEXT_MAX` in `core/feeds.ts`); readers wrap what they get — never re-truncate display text into shorter stored data.
- Consistent look across all providers: headline + description (indented, wrapped) + origin link.
- Header-zone lines stay single strings (a multi-node chips row once overprinted the line below); glyphs beyond `▍ ▸ ▲ · > …` have already bitten once.

Consumer-machine safety — the "works in dev, breaks on install" bug class, enforced by `tests/package.test.ts`:

- `tui.tsx` line 1 MUST stay `/* @jsxImportSource @opentui/solid */` — consumer installs have no repo tsconfig above them; without the pragma the transpiler defaults to React and the TUI fails with `Cannot find package 'react'`.
- The package ships its own `tsconfig.json` (in `files`) — second safety net.
- Never import React anywhere; never `__dirname` / `process.cwd()` / absolute paths in shipped files — anchor every access to `join(homedir(), ".config", "waitfeed", ...)`.
- Slot-rendered rows must NEVER size from `process.stdout.columns` — rows span `width="100%"` of the parent box, the headline is a `flexGrow` cell that wraps and is NEVER truncated (ticker-layout test).

Claude Code adapter:

- The card rides the host's `AbovePrompt` band (`claude-mod/hooks/register.js`), gated on the host's own `e.props.isWorking` — no ledger, no statusline. The retired statusline-era design (ledger, instant-paint flip, Esc transcript watcher) is gone; init still prunes its leftovers, so read the migration note in `packages/waitfeed/claude/README.md` before touching hook wiring.

## Release checklist

- Publish root is `packages/waitfeed/` (root package.json is the private `waitfeed-dev` harness).
- Dependencies are EXACT-pinned — bump deliberately per release, never silently.
- `overrides` don't travel with a published package — re-check `npm audit` and a tarball consumer-install at each release.
- `npm run preview` previews the tarball; `package-lock.json` is always excluded from it.
